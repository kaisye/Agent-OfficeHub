# Security — how the 8 safety rules are enforced

Each rule is enforced in code and covered by a test. Paths are relative to the repo root.

| # | Rule | Enforcement | Tests |
|---|---|---|---|
| 1 | Others' text is data, labelled untrusted | `packages/db/src/untrusted.ts` wraps every item authored by someone other than the token owner as `{trust:"untrusted", authorMemberId, authorAgentId, content}` (own content: `trust:"self"`). Used by MCP `list_inbox` / `read_board` (`apps/mcp/src/app.ts`) and `GET /agent/inbox` (`apps/api/src/app.ts`). Every MCP response starts with `UNTRUSTED_NOTICE`, tool descriptions repeat it, and the server `instructions` field carries it. External strings (GitHub PR titles, status text, request titles) are wrapped too. The hook CLI keeps items JSON-encoded inside a marked data block (`apps/agent-hooks/src/format.ts`). | `apps/mcp/test/mcp.test.ts` (list_inbox, read_board), `apps/api/test/api.test.ts` (/agent/inbox), `apps/agent-hooks/src/format.test.ts` |
| 2 | No agent-to-agent command path | There is no MCP tool that sends, decides, or addresses another agent; agents can only create/update DRAFTS addressed to a human's inbox. Tool set is exactly `McpTools` (5). A reply draft is only ever read by the receiving human (and that human's agent as untrusted data). | `mcp.test.ts` "exposes exactly the 5 contract tools", "no tool can record decisions or send" |
| 3 | Outbound actions need a human session | `canTransition()` (shared) is the only way a request status changes (`packages/db/src/requests.ts::actOnRequest`); send/send_reply/accept/follow_up/cancel are `humanOnly`. Human routes only accept the `oh_session` cookie: a global middleware in `apps/api/src/app.ts` rejects ANY `Authorization: Bearer` header on non-`/agent/*` routes with 403 `human_only` (even if a cookie is also present, and it audits the attempt). `recordDecision`/`createAgent`/`revokeAgent`/audit/handoff/mascot additionally call `requireHuman()` in `packages/db/src/core.ts`, so the rule holds even if a route were miswired. Decisions store `decided_by_id` referencing `members` (an agent can never be the decider). | `api.test.ts` "agent token is rejected on send / accept / recordDecision", `db/test/integration.test.ts` flow + decisions, `db/test/unit.test.ts` transitions |
| 4 | No secrets stored | `packages/db/src/secrets.ts` (gitleaks-style rules: OpenAI `sk-`/`sk-proj-`, Anthropic `sk-ant-`, GitHub `ghp_/gho_/github_pat_`, AWS `AKIA`, Google `AIza`, Slack `xox*-`, private key blocks, generic high-entropy `api_key=…`). `guardSecrets()` in `requests.ts` runs BEFORE any write transaction on: request title/body, action bodies (draft/reply/follow-up), status `doing`/`branch`, decision title/body/rationale, agent label. A hit throws 422 `secret_detected` naming the rule + field (never the value), writes nothing, and appends an audit row with only `{rule, field}`. | `db/test/unit.test.ts` (rules), `api.test.ts` "secret in a message", `mcp.test.ts` "secret in send_request" |
| 5 | One scoped, revocable token per agent | `packages/db/src/tokens.ts`: `oh_agent_` + base62 of 32 random bytes; only SHA-256 hex is stored (`agents.token_hash`), plus an 8-char display prefix. Scopes are checked per tool before the call (`apps/mcp/src/app.ts`, 403 `insufficient_scope`) and again in the services (`requireScope`). Revocation is checked on every request (`authenticateAgent`, 401 `token_revoked`, audited). A token is bound to its owner: all writes use the owner's member id. | `db/test/unit.test.ts` tokens, `mcp.test.ts` scope/revoked, `api.test.ts` agents |
| 6 | Row-level security per workspace | `packages/db/migrations/0002_rls_roles.sql`: RLS enabled on every tenant table with policy `workspace_id = current_setting('app.workspace_id', true)::uuid` (USING + WITH CHECK). The app connects as `officehub_app` (NOSUPERUSER, NOBYPASSRLS; `packages/db/src/client.ts::appUrl`). `withWorkspace()` sets `app.workspace_id` with `set_config(..., true)` (= `SET LOCAL`) inside a transaction. With no context the app role sees nothing. Pre-auth lookups (slug, token hash, session hash, member by id/GitHub login) use five narrow `SECURITY DEFINER` functions, not a bypass role. The owner role is used only by migrate/seed/test fixtures. | `db/test/integration.test.ts` "row-level security" (unfiltered query, foreign insert, role flags) |
| 7 | Append-only audit (and events) | `events` and `audit_log`: the app role has only SELECT/INSERT grants AND `BEFORE UPDATE OR DELETE` triggers raise an exception (so even the owner role cannot mutate; only TRUNCATE by the owner for dev reseed). Audit rows are written by services for every write (`audit()` in `core.ts`), by the API middleware for every human read (`apps/api/src/app.ts`, `/w/:slug/*`), for denied/failed writes, and by the MCP pipeline for every tool call (agent id + owner + `via`). Rows never contain message bodies. | `db/test/integration.test.ts` "append-only", `mcp.test.ts` audit, `api.test.ts` audit |
| 8 | Per-agent rate limits | `packages/db/src/ratelimit.ts` token buckets per agent id: 60 req/min total, `post_status` 6/min, drafts (`send_request` + `reply_draft`) 20/hour (env-overridable). MCP checks before the SDK runs (`apps/mcp/src/app.ts`), `/agent/*` checks in `apps/api/src/app.ts`; both return 429 `rate_limited` with `Retry-After`. | `db/test/unit.test.ts`, `mcp.test.ts`, `api.test.ts` |

## Visibility (contract C13)

`packages/db/src/requests.ts::viewFor` + shared `canSeeMessage`: a request is visible to its asker, receiver and (humans with role admin, read-only). A draft request is visible only to its asker; unsent drafts only to the owning side; admins never see drafts. Agents are never admin-viewers. Applied to `board.openRequests`, `listRequests`, inbox, `request.*` events on the board, SSE change notifications (`canViewRequest`) and MCP. Actions on a request you cannot see return 404.

## Other controls

- **CSRF**: state-changing cookie routes require header `x-officehub-csrf: 1` (forces a CORS preflight that only `WEB_ORIGIN` passes) and, when the browser sends `Origin`, it must equal `WEB_ORIGIN` (403 `csrf_failed`). Cookie: `oh_session`, httpOnly, SameSite=Lax, Secure when `WEB_ORIGIN` is https; stored as SHA-256 in `sessions`, 7-day TTL.
- **CORS**: only `WEB_ORIGIN`, with credentials.
- **Webhook**: HMAC-SHA256 `X-Hub-Signature-256` verified with a constant-time compare over the raw body before anything is parsed; missing/invalid -> 401 `bad_signature`; idempotent on `X-GitHub-Delivery`.
- **OAuth**: signed state cookie (HMAC with `SESSION_SECRET`), only pre-created members can sign in.
- **Body limit** 512 KB; all input validated with shared zod schemas; errors use the shared `ApiErrorCode` set.

## Known limits

Secret scanning is pattern/entropy based (can miss novel formats, can false-positive on long random identifiers next to words like `token=`). Rate-limit buckets are in-process (API and MCP each have their own; restart resets them). The audit table is append-only for the app and owner roles but a Postgres superuser can still drop triggers.
